# MAX Chat · GREEN-API (тестовое задание)

Минималистичный веб-чат на **React + Vite** для отправки и получения текстовых
сообщений в мессенджере **MAX** через **GREEN-API**. Интерфейс ориентирован на
[web.max.ru](https://web.max.ru/): список чатов слева, переписка справа.

Сделано в рамках тестового задания «Фронтенд разработчик React».

## Возможности

- Вход по `idInstance` / `apiTokenInstance` (проверяются запросом `GetStateInstance`)
- Создание нового чата по номеру телефона получателя — номер резолвится в настоящий
  `chatId` методом [`CheckAccount`](https://green-api.com/v3/docs/api/service/CheckAccount/)
  (в MAX `chatId` — непрозрачный числовой идентификатор, а не `phone@c.us`, как в
  WhatsApp, поэтому подставлять номер телефона напрямую нельзя — см. раздел ниже)
- Отправка текстовых сообщений — метод [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/)
- Получение входящих сообщений в реальном времени — long polling
  [`ReceiveNotification` / `DeleteNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/)
- История переписки и учётные данные сохраняются в `localStorage` браузера
  (никакого бэкенда — запросы уходят из браузера напрямую в GREEN-API)

Список того, что **сознательно не реализовано** (см. требование задания
«максимально простой интерфейс с минимальным набором функций»): вложения,
группы, статусы прочтения, редактирование/удаление сообщений, несколько
устройств одновременно.

## Стек

React 19, Vite, обычный CSS (без UI-фреймворков и стейт-менеджеров — для
такого объёма функциональности они избыточны).

## Локальный запуск

Требуется Node.js 18+.

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

Для сборки продакшен-версии:

```bash
npm run build
npm run preview
```

## Как пользоваться

1. Зарегистрируйте инстанс в [личном кабинете GREEN-API](https://console.green-api.com/)
   и авторизуйте его приложением MAX (раздел инстанса → подключение / QR-код).
   Если тестируете без доступа к MAX, задание допускает WhatsApp — процесс
   авторизации инстанса аналогичен, менять код не нужно.
2. **Важно:** в настройках инстанса (`SetSettings` или личный кабинет) поле
   `webhookUrl` должно быть пустым, а получение входящих сообщений включено —
   иначе уведомления не попадут в очередь `ReceiveNotification`.
3. Откройте приложение, введите `idInstance` и `apiTokenInstance` из личного
   кабинета. Если у инстанса указан отдельный хост API, разверните
   «Указать другой хост apiUrl» и впишите его — иначе используется общий
   `https://api.green-api.com`.
4. Нажмите «Новый чат», укажите номер телефона получателя в международном
   формате без «+» (например `79991234567`).
5. Напишите сообщение и отправьте. Ответ собеседника из мессенджера появится
   в чате автоматически, без обновления страницы.

## Деплой (демонстрация в интернете)

В репозитории уже настроен workflow `.github/workflows/deploy.yml`, который
собирает проект и публикует его на **GitHub Pages** при каждом push в
`main`/`master`. Чтобы включить его после создания репозитория на GitHub:

1. Запушьте код в свой репозиторий.
2. Зайдите в **Settings → Pages** и выберите **Source: GitHub Actions**.
3. Дождитесь завершения workflow во вкладке **Actions** — ссылка на сайт
   появится там же и в разделе Pages (обычно вида
   `https://<username>.github.io/<repo-name>/`).

Альтернатива без Actions — импортировать репозиторий в
[Vercel](https://vercel.com/new) или [Netlify](https://app.netlify.com/start):
команда сборки `npm run build`, папка публикации `dist`. Проект — обычный
статический SPA без бэкенда, поэтому подходит любой статический хостинг.

## Устройство chatId в MAX (важно!)

В WhatsApp `chatId` всегда равен `номер_телефона@c.us`. В MAX (v3 API) это
**не так**: `chatId` — непрозрачный числовой идентификатор (например
`"10000000"`), который сервер MAX присваивает сам и никак не выводится из
номера телефона. `phoneNumber@c.us` в `SendMessage` поддерживается только для
обратной совместимости при отправке — а во входящих вебхуках уже приходит
настоящий `chatId`, который с этим значением не совпадает. Поэтому приложение
не подставляет номер телефона напрямую, а сначала резолвит `chatId` через
[`CheckAccount`](https://green-api.com/v3/docs/api/service/CheckAccount/) при
создании чата — и дальше и отправляет, и сопоставляет входящие сообщения
именно по нему. Подробнее: [Важные отличия v3](https://green-api.com/v3/docs/important-differences/#chatid).

## Диагностика: сообщения отправляются, но ответы не приходят

Если после отправки собеседник получает сообщение, но его ответ не
появляется в приложении — проверьте по порядку:

1. **Настройки инстанса.** В личном кабинете (или методом `GetSettings`)
   убедитесь, что `incomingWebhook: yes` и поле `webhookUrl` пустое. Без этого
   сервер вообще не кладёт входящие уведомления в очередь `ReceiveNotification`.
2. **Консоль браузера (F12 → Console/Network).** Приложение крутит long polling
   `ReceiveNotification`/`DeleteNotification` в фоне; если запросы падают
   (например, из-за неверного `apiUrl`), это будет видно в Network как ошибки.
3. **Один и тот же инстанс в нескольких вкладках/приложениях одновременно.**
   `ReceiveNotification` — это общая очередь: два одновременных потребителя
   «расхватывают» уведомления друг у друга. Держите открытым только один клиент.

## Известные ограничения GREEN-API, учтённые в реализации

- `ReceiveNotification` — это общая очередь уведомлений инстанса: если запустить
  два экземпляра приложения на одном инстансе одновременно, они будут
  «отбирать» уведомления друг у друга. Для теста это некритично.
- Каждое полученное уведомление обязательно удаляется через
  `DeleteNotification`, иначе оно будет возвращаться повторно.
- Дедупликация сообщений сделана по `idMessage`, чтобы сообщение не
  задваивалось, если, например, было отправлено с телефона и одновременно
  прилетело уведомление о нём.
